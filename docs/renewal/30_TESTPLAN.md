Platform rule: a test that cannot run on an OS carries `@pytest.mark.plat("posix"|"windows")`; it is *absent* (not skipped) elsewhere; each REQ still needs a pass on >= 1 required OS. Real LibreOffice integrations carry the registered `soffice` marker. The six required installed-wheel cells run `-m "not release and not soffice" --runxfail`, requiring zero skipped tests. The single required `legacy-libreoffice (ubuntu-24.04, 3.14)` job installs headless Writer and Impress from apt and runs `-m soffice --runxfail`, enforcing a nonempty JUnit with zero skipped/failed/errored cases. Its JUnit, registry and independent collection are G-02 sources. Local real-tool tests may skip when soffice is absent; fake-soffice coverage always runs in required cells. A skip/xfail in either required CI phase is failure.

## 2. Traceability mechanism (R20)

1. **Markers.** Engine: `@pytest.mark.req("REQ-...", ...)`, `@pytest.mark.cov("S<n>","FM<n>")` (exactly one primary cell), `@pytest.mark.fx("FX-nn", ...)`. `scope("schema")` marks common schema/equivalence assertions rather than actual source-class execution. Test id = function-name prefix `test_T_ASM_06_<slug>` / `test_CT_08_...` / `test_PT_05_...`. `conftest.py` copies markers to junit `<property>` (`req tid cov fx plat`).
2. **Jest.** `req("REQ-SHL-02", "REQ-SHL-12")("JT-02 <description>")` helper builds the title `REQ-SHL-02 REQ-SHL-12: JT-02 <description>`; it throws at registration on unknown/duplicate ids. `jest-junit` titles are parsed by `trace.py`; M5-O01 requires exact unique expanded identities, not counts. Before execution run `python tools/trace.py collect-shell --output build/trace/collection-shell-<runner>.json`; this uses a separate full-suite Jest --collectTests registration mode (no test/hook bodies), seals source/config/spec bytes and candidate identity, and emits a v3 registry. Scoring rejects missing/duplicate/substituted/stale/skipped/failed cases and requires all expanded cases for each registered source title.
3. **Registry.** Independent full pytest collection and expanded Jest registration collection bind per-target evidence; AST/source discovery writes `build/trace/registry.json`.
4. **Meta-tests** (`T-META-*`, first in CI, no Core needed). Spec REQ ids = definition lines `^(- )?REQ-[A-Z]+-[A-Za-z0-9]+` of `10_SPEC.md`, `20_SHELL.md`, `25_PACKAGING.md` (deleted ids exempt). FAIL if: a spec REQ has 0 registered tests; a marker names an unknown REQ; a test lacks `req`; test ids duplicate or break the grammar; a `fx` id is missing from the manifest; a golden differs from `GOLDEN.lock` or was made by another Core; registered `req` set differs from section 4 (marker may be a superset, never a subset); this file omits a spec REQ or names an undefined one; a matrix cell is neither covered nor N/A-with-reason.
5. **Mutation self-test (PT-10):** copy of repo with (a) a marker deleted, (b) an invented REQ id, (c) a fixture removed -> each makes `trace.py check` exit non-zero.
6. **Results.** `trace.py report` emits registration/applicability views only. `trace.py score` reads JUnit from the six engine cells, three shell cells and packaging cells. Test PASS = ran and passed on every expected cell. REQ COVERED = >= 1 PASS and none FAIL. Output separates **automated** results from **manual** sign-offs (MAN) and never merges them into one coverage figure.
7. **Matrices** (section 5) are generated only from markers + `matrix.toml` + fixture manifest.
