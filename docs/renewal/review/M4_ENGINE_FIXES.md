## Evidence design and scope

Collection happens once separately for each JUnit's interpreter/phase. The collector owns its fixed complete `engine/tests` argv, disables plugin autoload, removes pytest selection environment, and never executes tests. The normal pytest hook preserves its execution selection separately. The scorer does not need pytest or recollect on the acceptance host; it verifies the recorded full collection, source/content/candidate bindings and exact JUnit selected identities. A restricted execution can be a useful focused local result but cannot certify an omitted required parameter.

`release.yml` now uploads `registry-release-*.json` and `collection-release-*.json` alongside each release JUnit, so artifact transport preserves the evidence actually consumed. Reference and compatibility uploads already retain the trace directory. Old v2 evidence without a canonical companion is intentionally insufficient for the repaired release guarantee; historical local receipts are not relabelled.

Temporary cleanup has no new public warning, provider call, daemon, global cache lock or PID-liveness heuristic. The OS lease, not a reused PID or timestamp, decides whether a recognized run is still active. Cleanup failure leaves a tree for a later run; unknown legacy directories are not deleted. This does not promise that a forced kill executes finally or returns exit130.
