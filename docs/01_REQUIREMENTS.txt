# MarkItDown-Flow: 오프라인 우선 이미지/표 처리 모듈 추가 요청

## 목적
현재 `markitdown_wrapper.py`의 이미지/스캔본 처리를 강화한다.
**오프라인 도구를 최대한 동원하고, 통합 신뢰도가 임계값 미달일 때만 AI를 호출**하도록 한다.
최종 목적: RAG 전처리(Gemini 타겟). 한국어 비중 높음.

## 핵심 설계 원칙
1. **오프라인 우선**: AI 호출은 최후 수단. 비용/프라이버시/속도 모두 절감.
2. **앙상블 기반 신뢰도**: 단일 엔진 신뢰도는 신뢰 불가. 여러 엔진 + 일치도 + 분산으로 통합 점수 산출.
3. **타입별 라우팅**: 이미지를 분류한 뒤 타입에 맞는 처리 적용 (photo/document/table/diagram/blank).
4. **구조 신뢰도 분리**: 표는 OCR 신뢰도가 아닌 "그리드 정합성" 기준으로 평가.
5. **Lazy Loading 유지**: 모든 신규 의존성은 기존 패턴대로 lazy import.

---

## 구현 요청 사항

### 1. 새 모듈 파일 추가
`src/utils/image_router.py` (또는 기존 구조에 맞는 위치)에 다음 컴포넌트들을 구현:

- `ImageClassifier` — 이미지 타입 분류 (photo/document/table/diagram/blank)
- `ImagePreprocessor` — deskew, denoise, binarize, super-resolution
- `OCREnsemble` — Tesseract + EasyOCR + PaddleOCR 앙상블
- `TableExtractor` — Table Transformer 기반 표 구조 추출
- `SmartImageRouter` — 위 컴포넌트를 조합한 메인 라우터

### 4. OCR 앙상블 + 통합 신뢰도
```python
def ensemble_ocr_with_confidence(image, lang='kor+eng') -> dict:
    """3개 엔진 돌려서 통합 신뢰도 산출"""
    # 엔진별 실행 (각각 try/except, 실패 엔진은 제외)
    # - Tesseract: pytesseract.image_to_data로 conf 추출
    # - EasyOCR: reader.readtext로 (text, conf) 리스트
    # - PaddleOCR: ocr.ocr로 결과 + score
    
    # 통합 신뢰도 공식 (가중합, 0~100):
    # - engine_conf_mean      × 0.30   # 엔진 자체 평균 신뢰도
    # - cross_engine_agreement × 0.35  # SequenceMatcher pairwise 평균 × 100
    # - length_consistency     × 0.15  # 1 - CV(텍스트 길이)
    # - cleanliness            × 0.10  # 1 - garbage_char_ratio
    # - conf_stdev_inverse     × 0.10  # max(0, 1 - stdev/30) × 100
    
    # garbage 정의: re.findall(r'[^\w\s가-힣.,!?;:\-/()]', text) / len(text)
    
    # 최종 텍스트 선택: agreement > 0.7일 때 max conf 엔진 결과 채택, 아니면 None
    
    return {
        'text': str | None,
        'confidence': float,            # 0~100
        'breakdown': dict,              # 각 항목 점수
        'engine_results': dict,         # 디버깅용 원본
        'should_escalate_to_ai': bool   # confidence < 70 or text is None
    }
```

### 5. 표 추출 + 구조 신뢰도
```python
def extract_table_with_structure_confidence(image) -> dict:
    """Microsoft Table Transformer로 표 구조 분석"""
    # 1. microsoft/table-transformer-structure-recognition로 셀 그리드 검출
    # 2. 각 셀 OCR (앙상블)
    # 3. 구조 신뢰도 산출:
    #    - row_alignment: 같은 row 셀들 y좌표 분산 (낮을수록 좋음)
    #    - col_count_consistency: 1 - stdev(row별 col 개수) / mean
    #    - cell_detection_conf: 셀별 검출 score 평균
    # 4. column_consistency: 각 열의 데이터 타입 일관성 (숫자/날짜/문자 비율)
    
    return {
        'table': list[dict],            # [{row, col, bbox, text, ocr_conf}, ...]
        'structure_confidence': float,  # 0~1
        'column_consistency': float,    # 0~1
        'unified_confidence': float,    # 위 둘 + OCR 가중합
        'should_escalate_to_ai': bool   # structure<0.5 or column<0.6
    }
```

### 6. 메인 라우터 (의사결정 트리)
```python
class SmartImageRouter:
    def route(self, image_source, ai_configs, cfg) -> dict:
        """
        1. 이미지 로드 → classify_image
        2. blank → 스킵
        3. photo → 메타데이터만 (llm_prompt 있을 때만 AI)
        4. document/diagram:
           - preprocess_scan (skew_angle 기록)
           - ensemble_ocr_with_confidence
           - skew_angle > 5도면 confidence *= 0.9
           - should_escalate_to_ai → True면 _run_ai 호출
        5. table:
           - extract_table_with_structure_confidence
           - should_escalate_to_ai → True면 AI hint와 함께 위임
        
        반환 형식은 기존 _run_offline / _run_ai와 호환되게:
        {"content": str, "status": str, "confidence": float, "method": str}
        """
```

### 7. 기존 `MarkItDownEngine`과의 통합
`MarkItDownEngine.run_conversion`에서 이미지 MIME 처리 흐름을 변경:

- 현재: `ai_target_mimes` 매칭 시 바로 `_run_ai` 호출
- 변경: 이미지 MIME이면 **먼저 `SmartImageRouter.route()` 호출**, 결과의 `should_escalate_to_ai`가 True일 때만 기존 `_run_ai` 폴백

## 우선순위
1. **P0**: `ImageClassifier`, `ImagePreprocessor` (deskew만), `OCREnsemble` (Tesseract + EasyOCR)
2. **P1**: `SmartImageRouter`, `MarkItDownEngine` 통합, ConfigManager 파라미터
3. **P2**: PaddleOCR 추가, `TableExtractor`
4. **P3**: Super-resolution, 고급 전처리

P0/P1까지만 구현해도 AI 호출이 크게 줄어들 것으로 예상.

## 검증
구현 후 테스트용으로 다음 이미지 케이스 처리 결과를 보여줄 것:
- (1) 깨끗한 한국어 문서 스캔 → 신뢰도 90+, AI 미호출
- (2) 기울어진 스캔본 → deskew 후 신뢰도 회복
- (3) 정형 표 → 표 구조 추출 성공
- (4) 자연 사진 → EXIF만, OCR 스킵

# MarkItDown Flow 운영 및 최적화 요건 정의서

## 1. 파이프라인 라우팅 및 엔진 최적화 (Pipeline & Routing)
- [ ] 단계별 강제 실행 방지
  - `exhaustive_mode: false` 설정으로 불필요한 후순위 API 호출 원천 차단
- [ ] 파일 특성에 따른 타겟 MIME 및 Phase 분리
  - 일반 사진, 인포그래픽 (`image/*`) -> Phase 2 (LLM Vision)에 할당하여 맥락적 설명 추출
  - 표, 체크박스가 포함된 문서/영수증 (`application/pdf` 등) -> Phase 3 (Azure Doc Intel, `prebuilt-layout`)에 할당하여 레이아웃 보존
  - 비디오/오디오 (`video/*`, `audio/*`) -> Phase 4 (Azure Content)에 제한적 할당
- [ ] 프롬프트를 통한 1차 분류 로직 (Phase 2)
  - `llm_prompt`에 "텍스트 위주 문서인지, 풍경/사물 사진인지 AI가 먼저 판단하여 처리 방식을 달리하라"는 지시어 추가
- [ ] 한글 OCR(Tesseract) 정확도 보정
  - `config='--psm 6'` (단일 텍스트 블록 가정) 옵션을 추가하여 한글 글자 사이 불필요한 공백 생성 문제 해결
  - (옵션) 영어/숫자는 Tesseract, 한글 구역은 EasyOCR로 처리하는 하이브리드 전처리 검토

## 2. API 비용 통제 및 장애 대응 (Cost & Failover)
- [ ] 외부 클라우드 예산 한도(Hard Limit) 설정
  - 대량 배치(Batch) 작업 시 과금 폭탄을 막기 위해 Azure, OpenAI 콘솔에서 예산 알림 및 차단 설정 필수
- [ ] 실시간 로깅 모니터링
  - 대규모 변환 작업 시 터미널에서 `tail -f ~/omnidata_logs/engine_YYYYMMDD.log`를 실행하여 HTTP 429(Rate Limit) 에러 즉각 인지
- [ ] Phase 2 (LLM Vision) 우회(Failover) 라우팅 구성
  - `ai_clients` 배열 순서를 [우선순위 고성능 모델] -> [대체용 저비용/무료 모델 (예: Gemini 2.0 Flash)] 순으로 구성하여 쿼터 초과 시 자동 대비

## 3. 파이썬 의존성 및 인프라 관리 (Environment Isolation)
- [ ] 전용 가상 환경(venv) 격리 구축
  - 시스템 전역 환경 충돌을 막기 위해 옵시디언 볼트(Vault) 외부 안전한 경로에 가상 환경 구축 (예: `~/.obsidian_python_env`)
- [ ] 플러그인 런타임 수동 바인딩
  - 플러그인 설정의 **Python path**를 가상 환경의 실행 파일 경로(`.../bin/python`)로 직접 지정
- [ ] 인프라 재구성(Teardown) 원칙
  - 의존성 꼬임 발생 시 개별 패키지 디버깅 대신, 가상 환경 폴더 전체 삭제(`rm -rf`) 후 재설치하는 방식으로 관리
- [ ] 미사용 모듈 원천 차단
  - 사용하지 않는 Phase(예: 4단계)는 파이썬 패키지(azure-ai-contentunderstanding 등) 설치를 생략하고 설정의 Endpoint 값을 비워둠
